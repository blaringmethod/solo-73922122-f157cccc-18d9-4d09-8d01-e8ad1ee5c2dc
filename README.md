# 期货连续合约结算价系统

把多个合约的期货结算价，按固定换月计划统一到**指定基准日的连续合约口径**；
并支持在连续价页按起止日查询**区间最大回落**（哪两天之间累计下跌最多）。
Flask + SQLite 单体应用，Docker Compose 一键启动。

## 口径定义

### 连续价（原有）

- 合约序列：一个**初始合约**（`ord=0`）+ 每次换月启用的新合约（第 k 次换月 → `ord=k`）。
- 换月价差：取**切换日前一交易日**的 `新合约结算价 − 旧合约结算价`（单位：整数分）。
- 某日 d 的连续价（基准日 B，B 不早于查询结束日）：

```
连续价(d, B) = 当日在用合约结算价
             + Σ { 各次换月价差 | d < 切换日 <= B }
```

- 当日原价缺失 → 连续价留空，注明缺哪个合约哪天的原价。
- 区间内某次换月缺报价 → 连续价留空，注明**最早**缺价换月及其待补的合约/日期。
- 连续价**实时计算、不落库**；改价不逐日回写。

### 区间最大回落（本次新增）

交易日排序为 d₀…dₙ₋₁。相邻交易日 dₗ → dₗ₊₁ 的涨跌，用**后一日在用合约 c** 的两笔结算价：

```
wₗ = price(c, dₗ₊₁) − price(c, dₗ)      # 后日减前日，同一合约
```

- **换月边**（后一日是切换日）同样取**新合约**在切换日与前一交易日的两笔价；
  此时即使**旧合约**在参考日缺价（换月价差 delta 因此为 NULL），这条边仍可核算。
- 任意两日 dₐ → d_b 的累计涨跌 = Σₗ₌ₐ…b₋₁ wₗ，回落金额 = −累计和（仅当累计和为负）。
- 两笔所需报价任一缺失，该相邻边即为**断点**；累计**不能跨过断点**。
- 输出最大回落的**起日、止日、金额（正整数分）**。同额时先取**较早的起日**，
  再取**较早的止日**（候选键 `(累计和, 起日下标, 止日下标)` 取最小）。
- 没有可核实的下跌（区间不足两个交易日 / 全是断点 / 所有连通段累计和均 ≥ 0）时，
  页面明确提示原因。
- 一次查询在同一个 SQLite 读快照事务内完成，只读同一已提交状态。

## 回落索引与复杂度

回落核算使用存在 SQLite 里的**堆式线段树**（边为叶，节点存整段和、最小前缀/后缀/
子段和候选及裁决坐标）：

| 表 | 作用 |
|---|---|
| `dd_state` | 单行状态：源表版本 `rev`、索引版本 `built_rev`、天数、树容量 |
| `dd_day_idx` | 交易日 → 全局下标（日期唯一索引，端点定位 1 行） |
| `dd_node` | 线段树节点（主键=堆编号，叶编号 `size + 边下标`） |

- **区间查询**：迭代式区间分解只按键读取 **≤ 2⌈log₂n⌉ 个 `dd_node`**
  （外加 `dd_state`/`dd_day_idx` 各常数行），O(log n)。
- **单笔补录/更正**：一笔报价至多影响「终于该日 / 起于该日」的**两条边**，
  每条边自叶向根重算并写 **⌈log₂n⌉+1 个节点**，合计 O(log n) 条记录写。
- 报价、换月价差（`rolls.delta` + Fenwick `bit_sums`）、回落索引在
  **同一个 `BEGIN IMMEDIATE` 事务**内提交；任何失败整体回滚，旧索引照旧供数。
- **日历全量替换 / 换月计划重建**后，按新配置**全量重建**回落索引（允许的例外路径）。
- **旧库首次补建**：新 schema 幂等建表，`dd_state.built_rev` 初始 −1；
  启动或首次查询发现 `built_rev ≠ rev` 即全量补建。
- `prices/calendar/rolls/contracts` 上的版本触发器会在**绕过应用直接改库**时
  推高 `rev`，下次查询自动自愈重建（受支持的页面/API 单笔补改仍走 O(log n) 增量路径）。

### 2 万交易日实测（本机临时库）

```
N=20000, 线段树容量 32768（深度 15）, dd_node 65535 行
全量重建 1.38s；保存日历（含逐行版本触发器）2.26s
非对齐窗口查询：dd_node 读取 16 条（上界 2*15+2=32），平均约 29ms/次（含事务）
单笔 upsert：dd_node 写入 32 条（=2*(15+1) 上界），约 2.9ms
```

## 数据结构与复杂度（连续价部分）

| 表 | 作用 |
|---|---|
| `calendar` | 交易日历 |
| `contracts` | 初始合约及每次换月启用的合约（`ord` 即启用次序） |
| `rolls` | 固定换月计划：切换日、前一交易日、新合约、价差（缺报价为 NULL） |
| `prices` | 按合约 + 交易日登记的整数分结算价（联合主键，重复提交即更正） |
| `bit_sums` | 换月价差的 **Fenwick 树**辅助表 |

- 价差区间求和、单点更新均为 **O(log n)**（n=换月次数）；辅助记录数 ≤ n，随换月次数只对数级增长。
- 单笔报价更新：写 1 行 `prices` + 至多重算 1 个价差（前一交易日唯一）+ Fenwick 单点 O(log n)
  + 回落线段树至多两条根路径 O(log 交易日数)，在一个 `BEGIN IMMEDIATE` 事务内**原子提交**。
- 一次取数在一个只读快照事务内完成，只看到同一已提交状态（SQLite 读快照）。

```bash
docker compose up --build
# 浏览器打开 http://localhost:8000/query ，拉到「区间最大回落查询」
```

### 网页演示换月与补价前后的回落

打开「连续价取数」页（`/query`），在「区间最大回落查询」顶部：

1. 点 **① 载入演示（补价前）**（会清空当前数据，有确认框）。场景含一次换月
   `DEMO_A → DEMO_B`（2026-03-05），且**旧合约 `DEMO_A@2026-03-04` 故意缺价**。
2. 补价前：最大回落 **200 分，2026-03-04 → 2026-03-05**，恰好是那条「换月边」
   （用 `DEMO_B` 两笔价 −200）；逐日表里能看到旧约缺价只造成它前一条边断点，
   并不影响换月边。另有 `DEMO_B@2026-03-09` 缺价造成两条相邻断点。
3. 点 **② 补入 DEMO_B 2026-03-09 = 39550 分，再查回落**：同一事务补价并增量更新索引，
   顶部提示条给出前后对照，最大回落变为 **690 分，2026-03-04 → 2026-03-11**
   （−200 +50 −300 −150 −90），逐日表高亮整段。
4. 可「撤销补价」反复演示，或再次「载入演示」（重复载入/重置已有数据已处理外键顺序）。

机器接口：`GET /api/drawdown?start=YYYY-MM-DD&end=YYYY-MM-DD`（兼容 `dd_start/dd_end`），
另有 `/drawdown?start=&end=` 302 到页面锚点。

## 使用流程

1. **交易日历**：每行一个 `YYYY-MM-DD`，全量替换保存（回落索引随之全量重建）。
2. **换月计划**：填初始合约代码，逐行添加「切换日 + 当日启用的新合约」后保存。
   切换日必须在交易日历内且严格递增；已有报价后禁止整体重建（防历史错配）。
3. **报价补录/更正**：选合约、交易日，填整数分价格。重复提交即更正；
   若该日是某换月的价差参考日，同事务自动联动重算价差；回落索引至多增量改两条边路径。
4. **连续价取数**：选开始日、结束日、基准日（不得早于结束日）→ 查询 / 下载 CSV
   （UTF-8 BOM，Excel 直开不乱码；缺价行连续价列留空并附说明）。
5. **区间最大回落**：在同一页下半部选回落起止日 → 查询；展示最大回落金额/起止日、
   逐日边价核对表（换月边、断点、最大回落段高亮）。直接用顶部连续价表单的
   start/end 查询时，也会顺带给出同一区间的回落结果。

## 未完成项 / 已知限制（如实说明）

- 当前沙箱环境**没有 docker / dockerd**，未能实际执行 `docker compose up --build`；
  已用镜像的同一条 gunicorn 启动命令在本机完整起服并跑通 HTTP 端到端。
  Dockerfile/compose 本身未改，新增 `app/demo.py` 会被既有 `COPY app ./app` 带入镜像。
- 逐日核对表为便于人工核验会按区间逐日取价，开销 O(区间天数)，属于**展示开销**；
  “核算最大回落”的索引查询本身仍是 O(log n) 节点读取。超大区间页面表格会很长，
  必要时后续可加分页或“仅显示断点/最大段”开关。
- 未提供删除报价的网页按钮（仅后端 `db.delete_price` 与演示“撤销补价”使用）。
- 回落索引是派生数据：极端情况下若手动绕过 SQLite 触发器/在旧版本文件上操作，
  可用一次 `db.rebuild_drawdown_index()` 或重新保存日历来自愈。
